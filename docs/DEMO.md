# 시연 스크립트 (PRD 7.3, 5~7분)

두 화면을 나란히 놓고 진행합니다. 같은 서버를 보고 있어서 모바일에서 한 행동이 관제 화면에 바로 나타납니다.

| 화면 | 주소 | 크기 |
| --- | --- | --- |
| 운전자 폰 | http://localhost:5173/m | 360×780 (브라우저 개발자도구 모바일 뷰 또는 실제 폰) |
| 관제 | http://localhost:5173/ops | 1920×1080 (또는 1440×900) |

화면에 나오는 시각(HH:MM)은 시뮬레이션 시계입니다. 서버를 켠 실제 시각에서 출발하므로 아래 예시와 다를 수 있습니다.

## 시작 전 준비 (발표 직전 1분)

1. `make seed` → `make dev` (끌 때는 터미널에서 Ctrl+C).
2. 관제 화면에서 **↺ 시나리오 리셋**을 두 번 누릅니다(두 번째 클릭이 확정). 데모 시나리오가 t=0으로 로드되고 시계는 멈춰 있습니다. 폰 화면 상단에 "정지" 배지가 보이면 정상입니다.
3. 폰에서 `/m`을 새로 엽니다 (이전 시연의 세션이 남아 있으면 리셋 후 새로고침).

## 단계별 진행

| # | 시간 | 화면 | 행동 | 기대 결과 | 말할 포인트 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0:00 | 슬라이드 | 기존 충전소 앱 화면 캡처를 보여줍니다. | — | "환경부 API는 충전 중이라는 것만 알려줍니다. 언제 끝나는지, 내 차례가 언제인지는 모릅니다." |
| 2 | 0:45 | 폰 | **내 차량 등록** → 차종 **아이오닉 5** → 목표 **90%** (현재 20%) → 충전기 **2번 · 100 kW** → **계산 근거 보기** | 하단 바에 "예상 37분 · 종료 HH:MM (범위 34~40분)", 근거 표에 **합계 36.7분**과 공식(P_eff, T1, T2) | "입력 3탭 안에 예상 시간이 나오고, 공식과 구간별 시간을 그대로 보여줘서 믿고 쓸 수 있습니다. 80% 이후 테이퍼링이 반영됩니다." |
| 3 | 2:00 | 폰 → 관제 | 폰: **시연 옵션**을 열어 "충전 완료 후 차량 이동 = 12분(방치 체험)" 선택 → **대기 등록**. 관제: **＋ 차량 추가**를 3번 | 폰에 "내 앞 N대 · 예상 HH:MM 시작"과 현재→내 차례 타임라인. 관제 간트차트에 폰의 차량과 추가한 3대가 충전기별 블록으로 나타남 | "순번은 충전기별 큐이고, 폰의 숫자와 관제 간트차트가 같은 데이터입니다." |
| 4 | 3:00 | 관제 | 배속 **10x** → **▶ 시작** | 시계가 흐르고 블록이 부드럽게 이동, 종료 시각이 갱신됨. 폰은 호출 → 충전 타이머 화면(`/m/charging`)으로 자동 전환 | "충전이 일찍 끝나거나 취소되면 뒤 블록이 바로 당겨지고, 서버가 0.5초마다 푸시해서 폰에도 곧바로 반영됩니다." |
| 5 | 4:00 | 관제 + 폰 | 배속 **60x**. 시나리오 차량이 도착하며 부하가 오릅니다. | 부하 게이지가 **90%**(주황)에 진입하고 "부하 경보" 배너. 이벤트 로그에 **출력 제한 / 시작 지연** 기록. 폰에는 출력 제한 또는 시작 지연 사유와 새 예상 시각 배너 | "계약전력의 90%를 넘기지 않도록 새 차량은 출력을 줄여 시작하거나 잠시 미룹니다. 이유와 시각은 운전자에게 반드시 안내합니다." |
| 5b | 4:40 | 관제 + 폰 | 폰의 충전이 끝나면 차량을 그대로 둡니다(방치 체험). 완료 5분 뒤 관제 상단에 **방치** 줄이 생기면 **운전자 알림** 클릭 | 폰에 "관제에서 차량 이동을 요청했습니다" 배너. 곧 차량이 이동하고 다음 대기자가 호출됨 | "방치된 차량은 다음 사람의 시간을 막습니다. 관제가 알림 한 번으로 해결합니다." |
| 6 | 5:00 | 관제 | 오른쪽 **부하 추이**와 상단 **KPI 카드** | 점선(제어 없음)이 계약전력선을 넘는 구간을 실선(VoltQueue)이 한도 아래로 눌러 놓고, 그 차이가 주황 면적. **피크 경감량** 카드에 수치, 회전수·평균 대기·부하율 카드와 전일 대비 화살표 | "같은 도착 순서로 제어 없는 경우를 나란히 시뮬레이션해서 효과를 숫자로 보여줍니다." |
| 7 | 6:00 | 슬라이드 | 한전KDN 관제 체계 연동, DR/V2G 확장 로드맵 | — | "충전기 상태는 환경부 API, 실제 전력값은 OCPP MeterValues로 교체하는 어댑터 구조입니다." |

시간 배분 팁: 1×로 두면 시간이 거의 흐르지 않습니다. 4단계에서 10x, 5단계에서 60x가 적당하고, 5b까지 60x로 약 1분 안에 도달합니다.

## 자동 재현 (리허설·비상용)

```bash
make e2e
```

Playwright가 자체 백엔드(:8100, 새 SQLite)와 프론트(:5174)를 띄우고 위 2~6단계를 폰(360px)과 관제(1920×1080) 두 브라우저로 재현합니다. 개발용 `make dev`·DB와 충돌하지 않습니다. 시스템에 Chrome이 필요합니다. 끝나면 `docs/screenshots/`에 화면이 저장됩니다.

## 문제가 생기면

| 증상 | 조치 |
| --- | --- |
| 폰에 "정지" 배지 | 관제에서 **▶ 시작** |
| 폰이 "대기 정보를 찾을 수 없습니다" | 리셋으로 세션이 지워졌습니다. 다시 등록하세요. |
| 리셋 버튼을 눌러도 안 지워짐 | 버튼이 "한 번 더 누르면 리셋"으로 바뀐 뒤 4초 안에 한 번 더 눌러야 합니다. |
| 화면 숫자가 코드와 다름 | `make dev` 창을 닫기만 했다면 옛 서버가 남아 있을 수 있습니다. 모든 python/node 프로세스를 종료하고 다시 실행하세요. |
| 네트워크·장비 장애 | 로컬 실행이 기본이라 인터넷이 필요 없습니다. 최후에는 `docs/screenshots/`와 녹화 영상을 사용하세요. |
